# Product Docs

This part of the docs answers a specific question:

What is already real in the product, and what product decisions have enough
shape to keep as versioned repo docs?

Use `docs/product/` for shipped-product summaries and PRDs.

Use Linear for active implementation tasks, prioritization, and future backlog.
Use [../manual/](../manual/) for user guides and [../design/](../design/) for
design rationale.

## Best Paths

If you want the shortest product route:

1. [shipped/README.md](shipped/README.md)
2. [prds/](prds/)

If you are learning the product and only want these as a companion:

- [../help/USER_GUIDE.md](../help/USER_GUIDE.md)

## What Goes Here

- `shipped/`: concise summaries of real product capabilities.
- `prds/`: product requirements and strategy docs that are stable enough to review.
- `_archive/`: old feature shelf material kept only for historical context.
